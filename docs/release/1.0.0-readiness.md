# Go Sensei 1.0.0 Release Readiness

Use this checklist before tagging `v1.0.0`. A green test run is necessary, but it is not enough for a release.

## Required Gate

Run the local release gate from a clean checkout of the release candidate:

```bash
npm ci
npm run release:check
```

The gate runs lint, the Vitest suite, a production build, and the high-severity dependency audit. GitHub CI for the release PR must show the same checks passing.

## Release Candidate Checklist

| Area | Required evidence before `v1.0.0` |
| --- | --- |
| Pull request state | The release candidate PR is ready for review, not draft, has clean merge state, and has passing GitHub checks. |
| Main branch | The release candidate has been merged to `main` before tagging. |
| Version metadata | `package.json` is set to `1.0.0` only in the actual release PR, after the candidate is accepted. |
| Production OAuth | The deployment has a dedicated GitHub OAuth App client id in `GITHUB_OAUTH_CLIENT_ID`; it must not rely on the development fallback. |
| Production smoke | The deployed app can load the board, start GitHub device login, reject missing production OAuth config, and complete the beginner guided-game first move. |
| Learning loop | A new beginner can follow the recommended path through guided play, lessons, problems, review, and progress without a dead end. |
| Release notes | `docs/release/v1.0.0-notes.md` summarizes learner-facing changes, known limitations, setup requirements, and verification commands. |

## Current Release Blockers To Check

Do not tag `v1.0.0` while any of these are true:

- The candidate work is still in a draft PR.
- `package.json` still says a pre-1.0 version.
- The candidate has not been merged to `main`.
- The production deployment has not been smoke-tested with a dedicated `GITHUB_OAUTH_CLIENT_ID`.
- Release notes do not explain the learning path, production auth requirement, and remaining known limitations.

## Production Smoke Notes

For the production smoke, record the deployment URL, commit SHA, OAuth app client id source, and the observed result for each flow. Do not record secrets or access tokens.
